## The shape of it

**The desks worked. The scripts did not.**

Every state script in this house reads the book repo. The house's own work lives
in `runs/`. Three scripts are blind to it, and one of them would have shipped a
wrong chapter.

Rule 8 forces outputs into `runs/`. The oracles were never taught to look there.
The two rules have been in conflict since the repo was created and no chapter had
ever been run far enough to expose it.

## Verified defects, ranked by cost

### 1. `next.py` tells the author to draft from a brief that failed its gate

Found independently by the Publisher and the Archivist.

```
$ python3 scripts/next.py --chapter 12
ch12: next stage is draft (draft.md missing) -> /gw-draft 12
```

Run minutes after the brief failed with `brief-gaps.md` on disk and two open ch12
inbox items. `gw-chapter/SKILL.md`'s own stage table says `research.md` *(and no
`brief-gaps.md` outstanding)* → draft. `grep` finds no reference to
`brief-gaps.md` anywhere in `next.py`.

Worse underneath: the script's documented rule #1 — "a chapter with an
`inbox.md` is parked" — reads `runs/chNN/inbox.md`, **a path nothing in this repo
has ever written.** The inbox `CLAUDE.md` mandates is `scripts/inbox.py`, which
writes `inbox/NNN-*.md`. The parked branch is dead code.

**Why this one is the worst:** `CLAUDE.md` forbids the Publisher from computing
"next" itself — `next.py` is the designated oracle precisely so a model cannot
drift. The single component nobody is allowed to second-guess is the one giving
the wrong answer.

*Proposed:* replace `chapter_state()` (`scripts/next.py:56-68`) so it parks on an
open `inbox/*.md` carrying `chapter: N` and stops at research while
`brief-gaps.md` is outstanding. **Named deletions:** the dead `if "inbox.md" in
have:` branch, plus the three other references to that non-existent convention in
`gw-draft/SKILL.md:78`, `gw-refine/SKILL.md:47`, `gw-board/SKILL.md:40`.

### 2. `okf_gate.py` cannot see anything this house writes

**Verified by the Publisher with a planted probe, then removed.** A citation
placed in `runs/ch12/okf/citations/` carrying `status: verified`,
`evidence_source: none`, `quote_form: verbatim` — the exact combination the
transcription rule exists to stop:

```
okf_gate: PASS - the caller may write prose.
GATE_EXIT=0
```

The gate validates only the book repo's bundle. It reported 89 citations while 8
new ones sat in the shadow tree, and the planted defect raised nothing.

The gate's own docstring says it exists because the first `gw-refine` ran no
citation check at all, "which made the replacement pipeline less safe on
citations than the one it replaces." **It still is, for everything the house
itself writes.** Rule 4: a gate that cannot see is not a gate.

*Proposed:* validate the shadow roots too. The Archivist verified the book's own
validator already accepts a shadow root unmodified — and doing so immediately
surfaced something nobody had seen: **11 of 15 internal links in this session's
citations use `](/okf/citations/`, a prefix the book's 54 existing links never
use** (all `](/citations/`). Those break the day inbox #007's migration lands.

**This proposal names no deletion.** By the house's own gate that makes it an
open item, not an accepted suggestion. The cheaper alternative that does fit:
add the shadow root to the existing `DERIVED` list in `session-stop.sh` (~25
words) — reports drift at Stop rather than gating before prose. Weaker, but
priced honestly.

### 4. `voice_check.py` prints "all HARD checks passed" over a HARD check that did not run

With no `--metaphor-family`, the metaphor check reports `[skip]` and
`UNCHECKED (not passed)` — then the headline reads `RESULT: all HARD checks
passed` and the script exits 0. FAIL correctly exits 1. So the only HARD check
that can silently not run is the one the drafter must remember to declare, and
the exit code calls it clean. **Rule 12: SKIP is not PASS.**

*Proposed:* exit 2 when any HARD check is SKIP; change the headline to
`RESULT: HARD checks passed, 1 UNCHECKED`. **Deletes** the sentence that is not
true.

*Not proposed:* changing the prefix matcher. It is documented, already noted in
the 2026-09-12 calibration entry, and the Publisher caught its effect by probing.
It worked.

### 5. `session-start.sh` re-anchors the review window mid-session

`.claude/hooks/session-start.sh:43` writes the SHA unconditionally on every
SessionStart — resume and post-compaction included. It read `287c629`, an auto-log
commit made *after* the interview's round-1 commit, so the window handed to the
Archivist **excluded 196 of `interview.md`'s 332 lines.** It only saw round 1
because it diffed from an earlier commit as well.

Costs nothing to the book; costs every future retro its first hour.

## What held under load

- **Rule 8 held.** The book repo is untouched: `git status` clean, no ch12
  artifacts, 89 citations unchanged, across two desks and a full session.
- **The clean-room gate worked and was worth its cost.** It certified it had not
  read the interview, and it caught ten real gaps including one that would have
  failed every draft on a counted check.
- **Rule 7 worked.** Three desk claims were re-verified independently; one — a
  reuse count — was wrong.
- **The Researcher refused a translation that search returned wrongly**, named
  the exact failure mode `06-sources.md` documents, and recorded the egress-proxy
  block in every affected citation rather than papering over it.
- **Inbox #008 and #009 are answerable cold**, without scrolling back.
- **The desks corrected themselves under challenge.** The Researcher retracted
  its own bounded-opening rationale in place and caught a self-contradiction
  during read-back that nobody had flagged.

## Environment finding

Every academic publisher host — sagepub, tandfonline, Wiley, PubMed bodies,
psychologicalscience.org, semanticscholar, and the Crossref API — is blocked by
this container's egress proxy. **No primary text was read for any citation this
session.** The house currently has no way to know that happened; it was reported
only because the desk volunteered it. `/gw-verify` cannot do its job from this
environment at all, which matters before the playground is deprecated.
